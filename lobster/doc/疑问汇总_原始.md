3. “数字员工”与“企业员工”的关系是什么？

当前系统里有：

- Employee
- Agent
- 15 个预设数字员工
- owner / assignee / permission bitmap

但真实企业场景里可能有几种模式：

┌──────────────────┬──────────────────────────────────┐
│       模式       │               说明               │
├──────────────────┼──────────────────────────────────┤
│ 数字员工独立账号 │ Agent 有自己的飞书/企微/ERP 身份 │
├──────────────────┼──────────────────────────────────┤
│ 人类员工授权代理 │ Agent 代表某个员工操作           │
├──────────────────┼──────────────────────────────────┤
│ 部门级共享 Agent │ Agent 代表 HR 部门、销售部门     │
├──────────────────┼──────────────────────────────────┤
│ 企业级系统 Agent │ Agent 使用企业统一服务账号       │
└──────────────────┴──────────────────────────────────┘

需要确认：

- Agent 是独立身份，还是代替某个人？  回答：Agent分两种，一个是员工分身，一个是独立agent。注意：独立agent的下属只会是agent，不能是自然人
- 外部系统里的操作人显示谁？      回答：先定一个名字，区别于自然员工
- 出问题时责任归属是谁？     回答：如果是员工分身，则责任归属员工，独立agent也有上级（自然人或agent），往上追溯上级，责任归属最近自然人上司。
- 是否允许一个 Agent 绑定多个外部账号？ 回答：允许，但正常情况下，一个agent同一类型外部账号如企微则只有一个，类比自然人。

这个会直接影响权限、审计、凭证、合规设计。

9. 数据合规  回复：这个问题上面由回复过了
   - 招聘数据、客户数据、财务数据、人事数据都敏感，需要明确保留/脱敏/删除策略。

    - 重试、回滚、补偿、人类接管、暂停任务，都需要业务规则。
