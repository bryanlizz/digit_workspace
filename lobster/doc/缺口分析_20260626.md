## 二、部分实现 — 待完善

### 2.1 详情面板记忆 — 硬编码未连接真实 API

**位置**：`src/components/office/DetailPanel.tsx:140`

**问题**：员工详情页的"长期记忆"区域显示的是固定 mock 数组，没有调用 `api.memory.search` 获取该 Agent 的真实记忆。

**影响**：用户看到的是假数据，与进化页面的记忆浏览器不一致。

**修复方案**：
```typescript
// 改为调用真实 API
const { data: memories } = api.memory.list.useQuery({
  agentId: employeeId, // 需要根据员工 ID 查找对应 Agent
  limit: 3,
});
```

---

### 2.2 Bad Case 列表 — 硬编码

**位置**：`src/pages/evolution/index.tsx:26`

**问题**：`const BAD_CASES = [...]` 是手写死数据。PRD 要求 Bad Case 从被驳回的任务中自动识别。

**修复方案**：
```typescript
// 改为从驳回任务中获取
const { data: rejectedTasks } = api.task.list.useQuery({ status: "REJECTED" });
// 渲染 rejectedTasks 而非 BAD_CASES
```

---

### 2.3 作战室聊天 — 纯前端模拟

**位置**：`src/pages/collaboration/index.tsx`

**问题**：
- 消息只存在前端 zustand store 中，刷新页面丢失
- Agent 回复是 `setTimeout` 模拟，不是真实 AI 调用
- PRD 要求"所有对话和决策自动记录"

**修复方案**：
1. 在 Prisma 中增加 `WarRoomMessage` 模型存储消息
2. 创建 `api.project.sendMessage` 和 `api.project.getMessages` 接口
3. Agent 回复改为调用 `taskEngine.executeTask` 或 `agentRuntime.runTask`

---

### 2.4 Agent 执行引擎 — 始终 mock 模式

**位置**：`src/server/agent/aiExecutor.ts`

**问题**：
- `USE_MOCK` 默认 true，即使配了 API Key 也只走 mock
- 执行结果通过 hack `mockRepo.tasks` 内部 Map 写回，不通过 Repository 接口
- 任务状态更新可能不生效（Object.assign 到内存对象）

**修复方案**：
1. 让 `aiExecutor.ts` 在有 API Key 时调真实 OpenAI
2. 让 `agentRuntime.ts` 通过 `taskRepo.update` 更新状态（需要扩展 IRepository 接口）
3. 执行结果写回 memoryService 持久化

---

### 2.5 知识图谱 — 数据源为空

**位置**：`src/server/knowledge/graphExtractor.ts` + `src/server/api/routers/graph.ts`

**问题**：
- `graphExtractor.extractFromTaskResult` 实现了抽取逻辑但从未被调用
- `KnowledgeGraph` 组件永远显示"暂无图谱数据"
- 没有入口触发图谱数据生成

**修复方案**：
- 在 `agentRuntime.runTask` 完成后调用 `graphExtractor.extractFromTaskResult`
- 或在知识库文档上传后触发实体抽取

---

### 2.6 路演模式 — 无真实相机动画

**位置**：`src/components/office/TourMode.tsx`

**问题**：PRD 要求"相机平滑移动到各区域"，但当前只做了文字轮播，没有控制 Three.js 相机。

**修复方案**：
- 使用 drei 的 `CameraControls` 或 `useFrame` 做相机插值动画
- 每个路演点设置 `cameraPosition` 和 `target`，用 lerp 过渡

---

### 2.7 AI 网关未集成到执行器

**位置**：`src/server/gateway/aiGateway.ts` → `src/server/agent/aiExecutor.ts`

**问题**：
- 网关能添加/管理 Key，但 `aiExecutor.ts` 没有调用 `aiGateway.getAvailableKey()`
- 配额限制、限流都不生效

**修复方案**：在 `executeWithAI` 中调用网关获取 Key，调用后记录用量。

---

### 2.8 项目参与者字段 — JSON 字符串兼容

**位置**：`prisma/schema.prisma` → `Project.participantAgentIds`

**问题**：SQLite 兼容改了类型（`String[]` → `String`），但前端仍在按数组使用。项目详情的参与者列表可能显示异常。
