## 一、产品概述

### 1.1 产品定义

**数智企业**是一个企业级 Agent（数字员工）操作平台，让企业能够创建、配置和管理 AI Agent，使其能够自动操作外部系统（飞书、Boss直聘、CRM、邮件等），完成招聘、销售、客服等业务场景。

### 1.2 核心价值

- **降低人力成本**：Agent 7×24 小时自动执行重复性任务
- **提升效率**：秒级响应，批量处理，减少人工操作时间
- **可审计可追溯**：所有操作记录在案，满足企业合规要求
- **灵活部署**：支持 SaaS 和私有化部署

### 1.3 产品形态

| 形态 | 说明 |
|------|------|
| **SaaS 版本** | 直接使用，支持多租户 |
| **私有化部署** | 部署到企业内网，支持定制 |

## 二、核心概念

### 2.1 Agent 类型

| 类型 | 说明 | 约束 |
|------|------|------|
| **员工分身** | 代表某个自然人员工的 Agent | 有上级（自然人或 Agent） |
| **独立 Agent** | 独立工作的 Agent | 下属只能是 Agent，不能是自然人 |

### 2.2 Agent 责任链

```
责任追溯链：
Agent ──► 上级（自然人或 Agent）──► 上级的上级 ──► ... ──► 最顶层自然人

责任归属：
- 员工分身 → 责任归属于该员工
- 独立 Agent → 责任归属于最近的上级自然人
```

### 2.3 外部账号绑定

| 规则 | 说明 |
|------|------|
| 一个 Agent 同一类型外部账号只能有一个 | 类比自然人 |
| 凭证归属 | 归属最近的上级自然人 |
| 凭证可见性 | Agent 不可见明文凭证 |

### 2.4 记忆隔离

| 维度 | 隔离方式 |
|------|----------|
| **按 Agent** | 每个 Agent 有独立的记忆空间 |
| **按项目** | 同一 Agent 不同项目记忆隔离 |

```
示例：
┌── 员工（自然人）
│   └── Agent "招聘助手"
│         ├── 项目 "校招" ─── 记忆：校招流程、候选人偏好
│         └── 项目 "社招" ─── 记忆：社招渠道、薪资谈判经验
```

## 四、功能需求

### 4.1 Agent 管理

| 功能 | 说明 | 优先级 |
|------|------|--------|
| Agent 创建 | 创建员工分身或独立 Agent | P0 |
| Agent 配置 | 设置 Agent 名称、技能、工作范围 | P0 |
| Agent 克隆 | 复制已有 Agent 配置 | P1 |
| Agent 上下级关系 | 设置 Agent 的上级和下属 | P0 |
| Agent 操作级别 | 设置 Agent 可执行的操作等级（L0-L6） | P0 |

### 4.2 任务管理

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 任务创建 | 创建任务并分配给 Agent | P0 |
| 任务执行 | Agent 自动执行任务 | P0 |
| 任务审批 | 关键操作需人工审批 | P0 |
| 任务状态 | 待处理、执行中、待审批、已完成、已驳回 | P0 |
| 任务结果 | 包含摘要、附件、外部记录、工具调用轨迹 | P0 |

**操作等级定义（L0-L6）：**

| 等级 | 能力 | 说明 |
|------|------|------|
| L0 | 只分析 | 不执行任何操作 |
| L1 | 只读查询 | 查询内部/外部系统 |
| L2 | 写入内部系统 | 修改内部数据 |
| L3 | 发送内部消息 | 内部通知、审批 |
| L4 | 发送外部消息 | 邮件、企微消息 |
| L5 | 修改业务数据 | 订单、合同、客户数据 |
| L6 | 关键动作 | 涉及资金、合同、人事 |

**任务结果格式：**

```typescript
interface TaskResult {
  summary: string;           // 执行摘要
  artifacts: Artifact[];    // 附件（文件、截图等）
  externalRecords: {         // 外部系统记录
    system: string;          // 系统名称
    id: string;              // 记录 ID
    type: string;            // 记录类型
  }[];
  toolCalls: ToolCall[];     // 工具调用轨迹
  approvals: Approval[];     // 审批记录
  errors: Error[];           // 错误信息
  nextActions: string[];     // 建议的后续动作
}
```

### 4.3 外部系统集成

#### 4.3.1 接入方式优先级

| 方式 | 优先级 | 说明 |
|------|--------|------|
| **API** | 首选 | 官方 API、MCP |
| **OAuth** | 支持 | 标准 OAuth 2.0 |
| **浏览器自动化** | 允许 | RPA、无 API 系统 |
| **Cookie/Session** | 支持 | 登录态持久化 |

#### 4.3.2 首批接入系统

| 系统 | 连接方式 | 功能 |
|------|----------|------|
| **飞书** | 官方 API | 消息、审批、文档、通讯录 |
| **Boss 直聘** | 浏览器自动化 | 登录、搜索、打招呼、简历 |
| **邮件** | SMTP | 发送邮件 |
| **短信** | 云 API | 发送短信 |

#### 4.3.3 Connector 框架

```typescript
interface Connector {
  id: string;
  name: string;
  type: 'api' | 'oauth' | 'browser' | 'smtp';
  credentials: CredentialRef;      // 凭证引用
  actions: ActionDefinition[];      // 支持的动作
  events?: EventSubscription[];      // 事件订阅
}

interface ActionDefinition {
  name: string;
  description: string;
  parameters: Parameter[];
  requiresApproval: boolean;        // 是否需要审批
  level: number;                    // 需要的操作级别
}
```

### 4.4 凭证管理（Vault）

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 凭证存储 | 加密存储 API Key、OAuth Token、密码 | P0 |
| 凭证绑定 | 凭证与 Agent/外部系统绑定 | P0 |
| 自动刷新 | OAuth Token 自动刷新 | P0 |
| Token 有效期 | 3 天不登录则失效需重新授权 | P0 |
| 凭证回收 | 员工离职后凭证处理 | P0 |
| 明文隐藏 | Agent 不可见明文凭证 | P0 |

**凭证归属规则：**
```
凭证归属最近的自然人上司
    │
    ├── 员工分身 → 凭证归属该员工
    │
    └── 独立 Agent → 往上查找最近的自然人，凭证归属该自然人
```

**员工离职处理：**
```
员工离职 → 员工分身变为独立 Agent → 下属 Agent 归属此 Agent → 上级改为员工原来的上级
```

### 4.5 人类接管机制

| 场景 | 处理方式 |
|------|----------|
| 验证码 | 转为任务派给自然人上司，等待回复 |
| 二次认证 | 同上 |
| 登录失效 | 同上 |
| 页面改版 | 同上 |
| 风控弹窗 | 同上 |
| 人脸/短信验证 | 同上 |
| 需要扫码登录 | 同上 |

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 接管触发 | 遇到无法自动处理的情况 | P0 |
| 任务派发 | 转为任务派给最近的自然人上司 | P0 |
| 远程接管 | 支持接管浏览器会话 | P1 |
| 接管后继续 | 接管完成后 Agent 继续执行 | P1 |
| 重试机制 | 尝试三次后触发人类接管 | P0 |

### 4.6 记忆系统

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 记忆写入 | Agent 可自动写记忆 | P0 |
| 记忆隔离 | 按 Agent + 项目隔离 | P0 |
| 记忆查询 | 支持按类型/时间/重要度筛选 | P1 |
| 记忆内容 | 用户偏好、成功经验、失败案例、常用格式 | P0 |
| 记忆保留 | 默认无限期保持 | P0 |
| 记忆删除 | 不可删除 | P0 |
| 记忆审核 | 不需要人工审核 | P0 |

**可记忆的内容：**
- 用户偏好
- 成功经验
- 失败案例（Bad Case）
- 常用格式
- 客户/岗位上下文
- 工具使用注意事项

**不应记忆的内容：**
- 密码/Token
- 敏感个人信息
- 未授权候选人资料
- 客户隐私
- 财务敏感信息

### 4.7 Bad Case 管理

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 自动识别 | 从驳回任务中自动识别 | P0 |
| 来源类型 | 人类驳回、外部失败、发送失败、投诉、审批被拒等 | P0 |
| 自动归因 | 自动分析失败原因 | P0 |
| 人工确认 | 归因后需自然人确认是否进入记忆 | P0 |
| 工具改进 | 用于改进工具选择 | P0 |
| Agent 评分 | 影响 Agent 评分 | P0 |
| 标注人 | Agent 或自然人都可以标注 | P0 |

## 五、审计与合规

### 5.1 审计范围

| 审计项 | 说明 | 优先级 |
|------|------|--------|
| 工具调用参数 | 记录每次工具调用的输入参数 | P0 |
| 请求/响应脱敏 | 敏感字段脱敏后记录 | P0 |
| 页面截图 | 执行关键节点截图 | P0 |
| 浏览器录屏 | 全程录屏（可选） | P1 |
| 操作前后状态对比 | 记录状态变化 | P0 |
| 审批记录 | 完整审批流程 | P0 |
| 外部系统返回 ID | 关联外部记录 | P0 |
| 可回放任务过程 | 可视化回放 | P1 |
| 导出审计报告 | 合规报告导出 | P2 |

### 5.2 审计规则

| 规则 | 说明 |
|------|------|
| 数据保留 | 默认 3 个月 |
| 脱敏字段 | 后期处理 |
| 查看权限 | 该 Agent 的所有上级（包括自然人和 Agent） |
| 不可篡改 | 审计日志不可篡改 |

### 5.3 合规目标

满足企业合规要求，包括但不限于：
- 操作可追溯
- 数据隔离
- 权限控制
- 审计留痕
